# عزل الحسابات على الجهاز

تاريخ التنفيذ: 2026-11-01. هذه المرحلة تعزل التخزين المحلي؛ لا تضيف مشاركة بين الحسابات ولا تحل كل تعارضات جهازين لنفس الحساب.

## البنية الحالية

| الجزء | التخزين |
|---|---|
| بيانات المستخدم المسجل | قاعدة مستقلة باسم LifeOS_user_USERID_v1، schema v7 |
| وضع بدون حساب | LifeOS_guest_v1، schema v7 |
| الصلاة والقرآن والتسبيح والتركيز والتفضيلات | workspaceStorage بمفاتيح تبدأ lifeos_workspace/SCOPE/ |
| أرشيف النسخة القديمة | LifeOS_workspace_system_v1.archives، ولا يُرفع للسحابة |
| جلسة Supabase Auth | تخزين SDK الأصلي؛ لا تدخل في workspaceStorage أو النسخ المحمولة |

المراجع: [workspaceScope](../../src/db/workspaceScope.ts)، [database](../../src/db/database.ts)، [AuthContext](../../src/context/AuthContext.tsx)، [syncIdentity](../../src/db/syncIdentity.ts).

كل صفحة تثبت هوية قاعدة البيانات والتفضيلات عند بداية تشغيلها. تسجيل الدخول والخروج أو تبديل الحساب يوقف عرض App ثم يغير مؤشر المساحة ويعيد تحميل الصفحة. لا يوجد تبديل لمتغير db وسط عمليات غير منتهية؛ أي callback قديم يظل مرتبطًا بقاعدة حسابه الأصلية. التبويبات الأخرى تتبع تغير الحساب، لأن جلسة Supabase في نفس المتصفح مشتركة وليست حسابًا مستقلًا لكل تبويب.

بوابة الحساب تنتظر قراءة الجلسة والترحيل والتهيئة قبل عرض البيانات. فشل قراءة أو تجهيز البيانات يعرض خطأ وإعادة محاولة؛ لا يعرض قاعدة حساب آخر كبديل. لا تُنتظر طلبات Supabase داخل callback تغير المصادقة. تنتهي استجابات الجلسة القديمة دون إعادة فتح حساب سابق.

عند فشل تجديد الجلسة بخطأ شبكة قابل لإعادة المحاولة، يسمح التطبيق بفتح قاعدة الحساب المختار سابقًا فقط إذا كانت موجودة بالفعل ولم يتغير مؤشر المساحة. يظهر وضع محلي واضح، ولا يُنشئ User أو Session وهميين ولا يسمح بالرفع. عودة الاتصال تعيد فحص الجلسة. غياب جلسة دون خطأ شبكة، وتسجيل الخروج الصريح، والأخطاء غير القابلة لإعادة المحاولة لا تُعامل كجلسة مصادق عليها. [سياسة التخزين دون اتصال](../../src/db/workspaceOffline.ts) مختبرة محليًا؛ اختبار المتصفح الفعلي ما زال مطلوبًا.

## منع رفع بيانات لحساب آخر

قبل السحب والرفع وإرسال عملية من الطابور، تُراجع هوية المساحة الثابتة ومؤشر المساحة الحالي والجلسة المعروفة ونتيجة SDK getSession. تغيّر الحساب في تبويب آخر أو انتهاء الجلسة يمنع الطلب. بعد قراءة السحابة وقبل التطبيق المحلي يتكرر التحقق. RLS في الخادم يبقى ضروريًا؛ عزل الجهاز لا يستبدله.

هذا عزل على مستوى التطبيق وليس تشفيرًا للملفات أو حماية من شخص لديه وصول كامل لملفات المتصفح وأدوات المطور. الملفات المصدرة تحتوي بيانات شخصية. لا توجد مشاركة تلقائية لبيانات العمل أو الأهداف أو البيت.

## التعامل مع البيانات السابقة

RoutineAppDB القديمة لم تكن تحمل ملكية موثوقة لكل سجل؛ لا نفترض أنها تخص الحساب الذي سجل الدخول الآن.

1. تُقرأ القاعدة القديمة دون ترقية مخططها أو حذف سجلاتها، ومعها مفاتيح التفضيلات المسموح بها فقط.
2. يُحفظ أرشيف في IndexedDB قبل بدء النسخ، مع JSON قابل للتنزيل، وعدد العمليات القديمة غير المرسلة.
3. تُنسخ السجلات المحمولة إلى وضع بدون حساب فقط، مع الاحتفاظ بالموجود إذا تصادف نفس المفتاح. يحتفظ الأرشيف بالقيم المتعارضة الأصلية.
4. لا تُعاد عمليات الطابور القديم تلقائيًا؛ قد تخص أكثر من حساب وتحتاج مراجعة. تبقى العمليات في الأصل والأرشيف، ولا تُحذف.
5. لا تُنسخ توكنات الدخول ولا حالة التركيز الجارية إلى الحسابات. الترحيل قابل لإعادة المحاولة ولا يعيد الكتابة فوق تعديلات تمت بعد نجاحه.

الإعدادات تعرض تنزيل نسخة البيانات السابقة. نقلها لحساب يتم باستيراد يختاره المستخدم ويراجع ملخصه. في حال فشل الترحيل بعد حفظ الأرشيف، تتيح بوابة الخطأ تنزيل النسخة السابقة أيضًا. الأصل لا يُحذف حتى بعد نجاح النسخ. يجب تحديث التبويبات والأجهزة القديمة؛ لا يضمن هذا الكود سلوك نسخة قديمة ما زالت تكتب في RoutineAppDB.

المصدر: [workspaceMigration](../../src/db/workspaceMigration.ts).

## الجلسات الجارية

عند مغادرة الحساب، تُغلق جلسة تركيز المهمة في قاعدة صاحبها وتُحفظ عملية رفعها في طابوره داخل معاملة واحدة، دون استخدام جلسة الحساب الجديد لإرسالها. تنظيف الحالة وسجل التركيز يعتمد معرف الجلسة لمنع مضاعفة الوقت عند إعادة المحاولة. التبديل لا يحسب وقت الحساب الجديد كعمل للحساب القديم. إعادة تحميل عادية لنفس الحساب لا توقف جلسة سليمة؛ تُنظف فقط حالة جارية تشير لجلسة مغلقة مسبقًا أو مهمة غير موجودة.

المصدر: [workspaceFocus](../../src/db/workspaceFocus.ts).

## JSON

نسخة format v3 ما زالت تضم 12 جدولًا محمولًا، ولكن من المساحة الحالية فقط. مفاتيح التفضيلات داخل الملف تبقى بالأسماء المحمولة القديمة دون prefix حتى يمكن نقلها. حقل workspace اختياري يوضح مصدر النسخة، ولا يغير الحساب أثناء الاستيراد. اختلاف المصدر عن المساحة الحالية يظهر تنبيهًا قبل التأكيد، ومؤشر الحساب وتوكنات Auth لا تُقبل ضمن localData.

## التحقق والحدود

الاختبارات المحلية تستخدم fake-indexeddb: فصل نفس المعرف في حسابين، فصل الطوابير والتفضيلات، منع تبويب قديم من المزامنة، فشل التخزين وإعادة الترحيل، عدم ترقية الأصل، منع نسخ التوكنات، وتوقف التركيز دون تكرار الوقت. تبقى تجربة تسجيل دخول حسابين فعليين على المتصفح والموبايل مطلوبة.

ما زال مطلوبًا: حسم تعارضات السحابة بإصدار سجل خادمي، نشر الحذف، تتبع كل التعديلات التي لم تُرفع، ومراجعة طابور النسخة القديمة مع مالك البيانات قبل إرساله. هذه المرحلة لا تعني اكتمال المزامنة دون تعارضات.


Current protocol (2026-11-01): local schema v8.
