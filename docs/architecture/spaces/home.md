# مساحة المنزل والأسرة

## الموجود فعليًا

### المخزون والجرد — منفذ

المسار `/home/inventory` داخل المطبخ بجانب الوصفات، مع مدخل مباشر من الرئيسية. يدعم البحث والمكان والتصنيف وفلاتر «استخدم أولًا / صلاحية قريبة أو متجاوزة / قليل / نفد». لا يخمّن تاريخ صلاحية ولا يعتبر الكمية المجهولة صفرًا.

الإدخال: صنف منفرد؛ دفعة منظمة؛ نص سريع؛ لصق خلايا Excel (بالعناوين لدعم اختلاف ترتيب الأعمدة، أو بالترتيب الموضح)؛ ورفع XLSX/CSV/TSV. مكتبة read-excel-file مثبتة بإصدار محدد وتحمّل عند اختيار XLSX؛ الورقة الأولى فقط وحد ٢ ميجابايت و٥٠٠ صف. المعاينة قبل التأكيد، ولا تُكتب البيانات أثناء القراءة. لصق جدول متعدد الخلايا في خانة الإدخال ينقله إلى صفوف منظمة.

الجرد يستبدل الموجود، والمشتريات تضيف كمية بوحدة مطابقة إلى كمية سابقة معروفة. اختلاف المكان أو الصلاحية يحتاج دفعة مستقلة. الجرد الجزئي لا يغيّر الغائب. الجرد الكامل لمكان واحد يعرض الغائب ويتطلب تأكيد اعتباره نافدًا. الحفظ الدفعي المحلي معاملة واحدة؛ إذا تغير أصل أحد الصفوف أثناء المعاينة يتوقف الحفظ كله. انتقال الصفوف للسحابة مستقل لكل سجل وقد يحتاج مراجعة تعارضات.

تاريخ آخر جرد منفصل عن آخر تعديل. سجل history داخل نفس الصنف ينتقل مع كمية الصنف في نفس عملية CAS؛ يحفظ قبل/بعد ونوع العملية والوحدة والفرق. الفرق «تغير مسجل» وليس استهلاكًا فعليًا مع مشتريات وهدر غير مسجلين. السجل شخصي قابل للاستيراد والتصحيح، وليس سجل تدقيق غير قابل للتعديل. حذف الصنف يحذف تاريخه النشط؛ تسجيل النفاد يحتفظ بالتاريخ. الإضافة للمشتريات إجراء صريح ولا يُضاف مخزون تلقائيًا عند إكمال الشراء.

Dexie v10 يضيف inventoryItems، وJSON v3 يضم الآن 14 جدولًا محمولًا. Supabase `inventory_items`: id text PK؛ user_id UUID FK إلى Auth مع cascade؛ name/category/location/unit/state/notes/package_unit نصوص؛ quantity/package_size/low_threshold numeric اختيارية؛ approximate/use_first boolean؛ expires_on date اختياري؛ last_counted_at timestamptz اختياري؛ history JSONB؛ created_at/updated_at timestamptz. لكل دفعة مختلفة سجل مستقل؛ لا يوجد قيد UNIQUE للاسم. فهرس (user_id,location). RLS قراءة المالك، وكتابة RPC محمية بالإصدارات فقط، مع قيود الكمية/الحالة والتحقق من history وآثار الحذف.

Migration المطبق: [add_inventory_audits](../../../supabase/migrations/20261101181201_add_inventory_audits.sql). نجح [اختبار Supabase بحسابين](../../../supabase/tests/inventory_integration.sql) مع ROLLBACK، وأكد فحص لاحق عدم بقاء الحسابات. المخطط السحابي الأقدم لا يمنع مزامنة باقي المساحات؛ المخزون يبقى محليًا مع رسالة عدم اكتمال حتى تفعيل جدوله.

واجهة الجرد تستخدم Ant Design (Table/Select/AutoComplete/Segmented/Modal/Card)، مع theme provider يتابع Light/Dark. التفاصيل الاختيارية خلف توسيع الصف؛ وعلى الموبايل بطاقات إدخال. مساحة المنزل ومكتبتها تحملان عند فتح المساحة للحفاظ على خفة بقية التطبيق. الثيم الفاتح يمتد إلى الهيدر وشريط الموبايل السفلي والحقول.

### تصميم وتنقل المنزل — منفذ

المساحة لها layout مستقل، مع تنقل: **الرئيسية، المطبخ، المشتريات، إدارة المنزل**. إدارة المنزل تجمع المهام والروتين المنزلي والصيانة ومشاريع المنزل؛ الروابط القديمة ما زالت تعمل. أُلغي شريط المساحات الفرعي المكرر لهذه المساحة فقط، وتوافق ترتيب السحب بين الأقسام مع التنقل الجديد.

الثيم موحد في القوائم ونوافذ الإضافة: خلفية فحمية دافئة #211D19، كروت #2D2722، نص كريمي #F5EEE5، طوبي #E3A27B للإجراءات وزيتوني للحالات والعناصر المختارة. القيم في home.css، وتنسيق الوصفات في recipes.css. التأثير محصور داخل المنزل ونوافذه، مع تعديل خلفية التطبيق أثناء فتح مسارات المنزل فقط.

الرئيسية تقدم المطبخ أولًا: فلاتر الوجبات وروابط مباشرة للوصفات المحفوظة، ثم معاينة المشتريات والأعمال المستحقة اليوم. لا تعرض وجبات مجدولة أو مخزونًا غير موجودين. الوصفات متاحة مباشرة من تنقل المطبخ، دون بانر وسيط.

المشتريات /home/shopping قائمة مستقلة، بإضافة مباشرة وبحث وفلاتر «لم تُشترَ / تم الشراء / الكل». تستخدم المهام الحالية بعلامات المشتريات للتوافق؛ لا توجد مزامنة تلقائية مع المخزون. المهام العامة لا تكرر المشتريات والروتين والصيانة. القوائم والرئيسية تتحدث عبر Dexie liveQuery بعد التعديل أو المزامنة.

المكونات منظمة باسم وكمية؛ تفاصيل الوصفة الإضافية قابلة للفتح بدل ظهور فورم طويل عند الإضافة. كل نوافذ المنزل تستخدم Radix Dialog مع focus trap وEscape، ولوحة سفلية للموبايل. الحقول بحجم 16px وأهداف لمس لا تقل عن 44px في المدخلات الأساسية.

التحقق: 173 اختبارًا محليًا، TypeScript والبناء/PWA، وlint للملفات المتغيرة. معاينة Chrome headless لم تنتج صورة في البيئة الحالية؛ المراجعة البصرية وتجربة جهاز موبايل فعلي ما زالت مطلوبة. لم يتغير مخطط Supabase في تحديث التصميم.

مكتبة الأكلات `/home/recipes` منفذة: الكل افتراضيًا، وتصنيفات متعددة لنفس الأكلة، وبحث بالاسم وبمكونات متعددة (كل المكونات المطلوبة)، ومفضلة ووسم خفيفة شخصي وفلتر ٣٠ دقيقة وترتيب الاسم/المدة/آخر تعديل. الاسم فقط مطلوب؛ المكونات باسم وكمية اختيارية، وخطوات التحضير والمدة والأفراد والملاحظات وروابط الصورة وYouTube اختيارية. الفيديو يفتح عند الطلب.

Radix Dialog يدير التركيز والإغلاق؛ نافذة للكمبيوتر ولوحة سفلية للموبايل. N للإضافة، / للبحث، Ctrl/Cmd+Enter للحفظ، وEsc للإغلاق مع مراجعة التعديلات غير المحفوظة. الحذف يحتاج تأكيدًا، ونسخة قديمة لا تستبدل تعديلًا أحدث أثناء التحرير.

Dexie schema v9: recipes بمفتاح id وفهارس title/updatedAt/*mealTypes. JSON v3 يشمل recipes ويقبل الملفات القديمة بدونه. Supabase public.recipes مربوط بالإصدارات والتعارضات والحذف؛ كل حساب يقرأ بياناته فقط. **المشاركة بين حسابين، ربط المخزون، وجدول الأسبوع لم يُنفذوا بعد.**

حقول Supabase: id text PK، user_id uuid FK إلى auth.users مع cascade، title text، meal_types text[]، ingredients JSONB من {name, quantity}، steps JSONB نصوص مرتبة، notes/image_url/video_url text، duration_minutes وservings أرقام اختيارية، is_favorite/is_light boolean، created_at/updated_at timestamptz. فهرس (user_id,updated_at). RLS يسمح SELECT للمالك؛ الكتابة عبر sync_apply_mutation فقط، واللقطة عبر sync_read_snapshot. Trigger يتحقق من JSON ويحدث sync_entity_versions. الكتابة المباشرة وanon ممنوعان.

Migration: [add_recipe_library](../../../supabase/migrations/20261101143722_add_recipe_library.sql). [اختبار backend](../../../supabase/tests/recipe_library_integration.sql) نجح بحسابين مؤقتين ثم ROLLBACK. إجمالي الاختبارات المحلية 173. المراجعة البصرية توقفت لأن أداة التحكم لم تستطع تأكيد URL؛ تجربة الموبايل الفعلية لم تُجرَ.

المسارات تحت /home: recipes, shopping, tasks, projects, routines, maintenance. مهام منزلية ومهام متكررة ومشاريع متعددة الخطوات وإجراء تالٍ وصيانة بقوالب جاهزة، داخل تصميم المنزل المخصص.

| الكيان | التخزين المحلي | Supabase الحالي |
|---|---|---|
| مهمة منزل | tasks مع spaceId=home | life_tasks مع metadata المهمة |
| روتين منزل | نفس المهمة مع isRecurring وrecurrenceRule | نفس الجدول مع recurring_completion_dates |
| صيانة | مهمة منزل مع نص/علامة في العنوان | لا يوجد نوع صيانة مستقل |
| مشروع تحسين | projects مع spaceId=home أو غير محدد للتوافق | projects موجود وspace_id يميز المنزل والعمل |

الصيانة تُستخرج حاليًا بكلمات في العنوان مثل صيانة/تكييف/سباكة/كهرباء/أجهزة/فحص أو بداية [. بعض تمييز المشتريات نصي أيضًا؛ لا تعتبره تصنيفًا منظمًا يمكن الاعتماد عليه كعقد backend. قواعد المهمة والمشروع في [المشترك](../shared-data.md) و[العمل](work.md)، والأعمدة الفعلية في [اللقطة](../supabase-current.md).

## الأجزاء المتفق عليها المتبقية

واجهة بيتنا تعرض ملخصًا محدودًا لما يحتاج تصرفًا: وجبة اليوم، استخدام أولًا، نواقص، ومهمة منزلية أو موعد. التفاصيل في أقسام المطبخ والمشتريات والمهام والصيانة والتحسينات والخروجات. عرض مريح للموبايل والبحث والفلترة، مع تصميم مختلف عن مساحة العمل.

### المطبخ والجرد

الجرد دوري، وليس مطلوبًا إنقاص الكمية مع كل استخدام. الإدخال المنظم السريع (اسم/كمية/وحدة/مكان) أساسي، بجانبه نص حر وصور ورق ومراجعة استخراج ونسخ خلايا Excel أو ملف. الصورة والذكاء الاصطناعي لا يحفظان نتيجة دون معاينة.

يفصل الإدخال بين شراء جديد يضيف كمية، وجرد يحدد الموجود الآن. الجرد الافتراضي يعدل المذكور فقط؛ عدم ذكر صنف لا يعني نفاده. جرد مكان كامل يحتاج مراجعة الأصناف الغائبة قبل تغيير حالتها. فرق جردين نقص مخزون تقديري؛ لا يسمى استهلاكًا دقيقًا مع مشتريات أو هدر غير مسجلين.

المجهول لا يساوي صفرًا. ادعم كمية دقيقة أو تقريبية أو موجود/قليل/خلص، ومكانًا غير محدد. احفظ عدد العبوات وحجم العبوة منفصلين عند معرفتهما. افصل تاريخ الصلاحية عن ملاحظة الحالة الفعلية مثل «استخدم أولًا»، ولا تخترع موعد صلاحية من الصورة.

### اقتراحات الأكل وجدول الأسبوع

مكتبة اقتراحات شخصية مشتركة، وكل أكلة تقبل أكثر من تصنيف: فطار/غدا/عشاء/سناكس/سندوتشات. عرض الكل افتراضي، والتصنيف فلتر لا قيد يمنع اختيار أكلة فطار للعشاء. الاسم مطلوب فقط؛ المكونات والكميات والخطوات والمدة والحصص والملاحظات ورابط الصورة ورابط YouTube اختيارية، والصورة والفيديو يمكن اجتماعهما.

البحث بمكون أو أكثر يقارن المكتبة بالمخزون، ويوضح سبب الاقتراح والنواقص وعدم يقين الكميات وحداثة الجرد. لا يضمن توفر حصة كاملة مع كمية مجهولة. الوجبة الخفيفة وسم يختاره المستخدم وليست حمية محسوبة طبيًا.

أيام العمل الأحد–الخميس. الجدول يقبل فطار الشغل/سندوتشات وغداء بعد العودة وعشاء اختياري وسناكس وmovie night، مع بواقي وتجهيز مسبق وأكل خارج البيت. اختيار وجبة لا يخصم المخزون تلقائيًا.

## بنية مقترحة للـbackend — أسماء مبدئية

| الكيان المقترح | الحد الأدنى للبيانات والعلاقة |
|---|---|
| InventoryItem | id، اسم، تصنيف، مكان، كمية ووحدة أو حالة مجهولة، وقت آخر جرد |
| InventoryLot | itemId، كمية العبوة/الدفعة، expiryDate اختياري، حالة الاستخدام؛ يميز صلاحيات دفعات نفس الصنف |
| InventoryAudit / AuditEntry | هوية الجرد وتوقيته ونطاقه جزئي/كامل، item/lot، الكمية السابقة والمعدودة، ملاحظات |
| Recipe / Ingredient / Step | هوية الوصفة، وسوم الوجبات، روابط، حصص، مكونات مرجعية أو نصية، خطوات مرتبة |
| MealPlanEntry | التاريخ ونوع الوجبة، recipeId أو ملاحظة/بواقي، حصص وملاحظات |
| ShoppingList / Item | القائمة والصنف والكمية وحالة الشراء ومصدر الاقتراح |
| MaintenanceDetail | taskId، نوع المشكلة/الجهاز، الفني والموعد والحالة والتكلفة الاختيارية |
| SharingGrant | مورد ونوعه، عضو وصلاحية؛ يخضع لتصميم المشاركة المشترك |

لا توجد هذه الجداول محليًا أو سحابيًا حاليًا. قبل التنفيذ يجب تثبيت الوحدات والدفعات والتعامل مع التكرار والتزامن. استخدم مهمة واحدة في Today مثل «شراء النواقص» مرتبطة بالقائمة بدل تحويل كل صنف لمهمة.

## نقل .NET والتوافق

افصل Inventory/Audits وRecipes وMealPlanning وShopping عن TaskService. نقل المهام القديمة إلى أنواع منظمة يحتاج معاينة، ولا يعتمد على الكلمات في العنوان وحدها. المشاركة اختيارية على القسم أو العنصر؛ امتلاك حساب زوج أو زوجة لا يمنح وصولًا تلقائيًا. أضف الكيانات الجديدة للنسخ المحمولة واختبارات الاستعادة مع كل ميزة.
